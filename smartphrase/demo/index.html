2Two views, one thing — edit either side

The model panel and the prose are projections of one instance object — there is no second copy to drift. Change the model and the prose rewrites itself; edit the prose (click a phrase, or edit the tag source below) and the model follows.

      3Template reuse — write once, instantiate many
      
  
      Reuse works in two directions. Within each study, every analysis below
     instantiates the same library building block — one transformation template with its valid
     smartphrases — and only the highlighted bindings vary; prose, model structure, method and traceability
     all come from the template. Across studies, a different block is drawn from the same
     Transformation Library v0.7, so the pattern holds over a different therapeutic area and a different
     endpoint type. Open any of them in the editor above.
      
  
      

      



      
  
      4Standards grounding — no private id space
      
  
      Every identifier the passage binds to, and which standard it grounds into. Entities a CDISC
     standard already covers resolve into that standard (USDM for study structure, ARS for analyses, STATO for
     statistical methods, NCIt for terminology); AC/DC ids cover only what is genuinely new. Identifiers not yet
     registered are flagged illustrative — the mechanism, not the final ids,
     is the claim.
      
  
      
  
      
  
      
    
      Why this survives a changing SAP structure
      
    
      The semantic layer is standoff: it is a graph fragment whose nodes
       anchor to spans of prose, not to a document schema. A sister initiative is defining a standard SAP structure
       (as M11 does for protocols) — whatever structure it lands on, the smartphrase layer attaches to its text
       unchanged, because nothing here depends on how the surrounding document is organised.
